V2Ray Console

基于 Web 的 V2Ray（v5）管理面板，提供可视化的配置编辑、启停控制和状态监控。

功能

  • Web 管理界面 — 浏览器中查看/编辑 V2Ray JSON 配置，支持可视化表单和 JSON 双模式
  • 启停控制 — 一键启动、停止、重启 V2Ray 核心
  • 系统代理一键开关 — 一键将系统全局代理指向本地入站（macOS / Windows / GNOME Linux），本机和内网地址自动绕过
  • 配置模板 — 内置 SOCKS5 / HTTP 等客户端模板快速上手；首位「SOCKS5 + 内网直连」模板用裸网段分流，无需 geoip.dat / geosite.dat 开箱即用
  • UUID 生成器 — 表单内一键生成随机 UUID，方便 VMess 用户配置
  • REST API — 支持远程管理，方便集成其他工具
  • 实时状态 — 自动轮询显示运行状态和版本信息

快速开始

前置条件

  • Go 1.21+
  • geoip.dat 和 geosite.dat — 仅当路由 / DNS 配置引用 geoip: / geosite: 前缀时需要；不用 geo 规则（如内置「内网直连」模板）可跳过
# 下载 geo 数据文件（仅当配置使用 geoip:/geosite: 规则时需要，否则可跳过）
curl -sL -o geoip.dat "https://github.com/v2fly/geoip/releases/latest/download/geoip.dat"
curl -sL -o geosite.dat "https://github.com/v2fly/domain-list-community/releases/latest/download/dlc.dat"

初始化配置

# 从示例配置文件创建实际配置（config.json 已 gitignore，需自行创建）
cp config.example.json config.json

然后用编辑器打开 config.json，将 your-server.com、your-uuid-here 等占位符替换为你的实际服务器信息。

编译运行

# 编译
go build -o v2ray-console .

# 启动（默认使用 config.json，仅本机可访问）
./v2ray-console -config config.json -port 8080

# 指定监听地址（例如允许局域网访问）
./v2ray-console -host 0.0.0.0 -port 8080

打开浏览器访问 http://localhost:8080。

参数默认值说明
-configconfig.jsonV2Ray 配置文件路径
-host127.0.0.1管理面板监听地址（仅本机）
-port8080管理面板监听端口

用户快速入门和操作手册

上一节讲了如何把 v2ray-console 跑起来。这一节讲打开浏览器之后怎么用——界面布局、每个区块能做什么、最常见的几个工作流、以及可视化操作中需要注意的细节。配置指南 章节列出了全部 JSON 字段；本节专注于在 Web 界面上的实际操作。

界面总览

管理面板从顶到底分四块：

  1. 顶栏：左侧是品牌标识和运行状态指示器（绿点=运行中、灰点=已停止、红点=异常）；右侧依次是「帮助文档（?）」「主题切换 🌙/☀️」「刷新配置 ↻」。
  2. 状态 Hero：大字号显示「运行中 / 已停止 / 异常」状态，附带 V2Ray 版本、运行时长（仅运行时显示）和响应延迟；右侧三个按钮：启动 ▶ / 停止 ■ / 重启 ↻。
  3. 概览四宫格：自动统计当前配置里的「入站数量 / 出站数量 / 路由规则数 / 监听端口数」，每个数字下面用协议色块展示明细（例如 socks ×2 · vmess ×1）。
  4. 配置卡片：核心工作区，又分两层：
    • 「流量走向」图（自动出现，描述规则如何把流量分发到不同出站）。
    • 「配置文件」编辑区，带「可视化 / JSON」两个标签页，外加「复制 / 导出 / 导入 / 保存」工具按钮。
  5. 快速模板：四个预设模板卡片，一键生成 SOCKS+VMess、HTTP+VMess、VLESS+Reality、Shadowsocks 客户端配置。

页面右下角是 Toast 通知，保存成功、复制成功、保存失败等所有反馈都会通过它弹出，3 秒后自动消失。

创建第一份配置

第一次打开 Web 页面会看到 「暂无配置」 引导界面。三种方式可以开始：

  1. 选模板：在引导页或下方「快速模板」区点一个模板。模板会填好入站、出站、传输设置的骨架，只需要再把服务器地址、UUID/密码、端口等信息改成你自己的。最推荐新手用这个。
  2. 从文件导入：点「从文件导入」（顶部工具栏或引导页都有），选择一个已有的 config.json，解析后会切换到可视化视图。
  3. 粘贴 JSON：切到「JSON」标签页，把配置粘进去。粘错格式不会丢之前的内容——它会报错并保持当前状态。

小贴士：不论从哪条路径进入，配置变更后页面标题会变成 ● V2Ray Console，标题前的小圆点表示有未保存的改动。点「保存」或按 ⌘/Ctrl+S 后小圆点消失。

可视化编辑模式

「可视化」标签是面向日常编辑的表单视图。从左到右有 6 个子标签：📥 入站 / 📤 出站 / 🔀 路由 / 📡 DNS / 📋 日志 / ⚙️ 策略+传输。点哪个就只渲染那一个区块，切换非常快。

每个区块的通用交互：

  • 添加：区块底部都有 + 添加 XXX 按钮，会追加一份默认值（比如入站默认 SOCKS5、出站默认 VMess）。
  • 删除：每条记录的右上角 ✕ 按钮。最后一条不能删（系统会弹「至少保留一个 XXX」的警告）—— V2Ray 本身要求至少有 1 个入站和 1 个出站。
  • 折叠 / 展开：每条记录是一个独立卡片，默认展开；点标题可以折叠，便于在配置多的时候浏览。
  • 协议切换：入站或出站卡片顶部的协议下拉切换后，下方的字段会自动重新渲染成新协议对应的字段（旧的协议专有字段会被丢弃）。

输入修改后会立即写入内存中的「状态对象」，但不会自动写盘——必须点「保存」才会落盘并触发 v2ray-core 重启。

入站配置

入站卡片顶部包含：监听端口、监听地址、协议、标签。下面是按协议分组的字段：

协议关键字段说明

vmess（入站）客户端列表（UUID / alterId / security）服务端场景使用，需要给每个用户发 UUID
vless（入站）客户端列表（UUID / flow / encryption / fallbacks）现代推荐的服务端协议
trojan（入站）客户端密码列表、fallbacks密码即身份
shadowsocks（入站）加密方法、密码选好 method 即可

每个 UUID 输入框旁边都有一个 🎲 骰子按钮，点一下就会生成新的 v4 UUID 并自动填入，同时触发 change 事件让状态同步。

卡片底部有一个可折叠的「高级设置（可省略）」区域，里面是 流量嗅探 开关和 destOverride 多选（HTTP / TLS / QUIC）。嗅探能自动识别 HTTP 代理请求里的真实目标地址，配合路由规则更精准。

出站配置

出站卡片的字段比入站多。最常用的是 vmess / vless / trojan / shadowsocks 四种代理协议，每种都需要填服务器地址、端口、用户凭据。卡片底部有两个可折叠的进阶区：

  • 传输设置：选 network（tcp / kcp / ws / h2 / quic / grpc）和 security（none / tls / reality），再下面会根据选择出现对应的子字段。改 transport / security 也会重新渲染下方。
  • Mux 多路复用：勾选启用，再填最大并发数（默认 8）。

除了代理协议，还有几个「非代理」出站：

出站典型用途
freedom直连出站，分流场景必配。常见 tag：direct
blackhole黑洞，匹配后丢弃流量。常见 tag：block
dns专用 DNS 出站，配合路由让 DNS 走代理

tip：出站的 tag 字段非常重要——路由规则就是按 tag 来引用出站的。建议用 proxy、direct、block 这种语义清晰的命名。

路由配置

「路由」标签页是配置最核心的部分。可视化界面把路由拆成三块：

  1. 域名策略 / 匹配器：domainStrategy（AsIs / IPIfNonMatch / IPOnDemand）+ domainMatcher（linear / mph）。大多数场景保持 AsIs + linear 即可。
  2. 规则预设：四个一键添加按钮：
    • 🏠 内网 IP：弹两个选择 — geoip:private（需 geoip.dat）或写死具体网段（无需数据文件）
    • 🇨🇳 本地 IP：同上，区别是分流到大陆 IP
    • 📡 DNS：把 53/UDP 直接走 direct（不代理 DNS 请求）
    • ➕ 自定义规则：添加一条空白规则，自己填
  3. 规则列表：每条规则是一个可折叠卡片，字段包括：ip、domain、network（tcp/udp/any）、port、protocol、inboundTag、outboundTag（下拉，列出当前所有出站 tag 和 balancer tag）。

关于 AsIs + linear：这是默认推荐的组合，理解起来其实很简单——

  • AsIs（域名策略）：不做 DNS 解析，直接拿客户端传来的域名原文（如 baidu.com）去匹配规则。好处是速度最快，也最贴合用户意图——访问 baidu.com 就匹配 baidu.com，不会因为 DNS 返回了某个 CDN IP 而被错误地分到代理分支。
  • linear（域名匹配器）：在规则集合里按顺序逐条比对，简单、可预测，调试时一眼就能看到「命中的第几条」。几十到几百条规则下，性能开销几乎可以忽略不计。

所以绝大多数配置保持 AsIs + linear 即可。只有在以下场景才需要切换：

  • 大量依赖 geoip: 做兜底（例如「国内 IP 直连，其余代理」）→ 把 domainStrategy 改成 IPIfNonMatch，让没命中的域名再按解析出的 IP 匹配一次 geoip: 规则。
  • 规则总数上千条、对每次匹配的延迟非常敏感 → 把 domainMatcher 改成 mph（最小完美哈希），用 O(1) 查找换更低的运行时开销；代价是启动时构建更慢，且每次修改规则后需要重建哈希表。

完整组合对照表

domainStrategydomainMatcher典型场景
AsIslinear默认推荐，绝大多数配置
AsIsmph域名规则上千条，且只按域名分流（无 geoip 兜底）
IPIfNonMatchlinear域名规则 + geoip 后置兜底（如「国内 IP 直连」），规则量适中
IPIfNonMatchmph上一条 + 大规则集
IPOnDemandlinear几乎纯靠 IP 分流，每次都先解析 IP
IPOnDemandmph上一条 + 大规则集

别名：mph 也可写成 hybrid；IPIfNonMatch 还接受 ip_if_non_match / ip-if-non-match 等下划线 / 中划线写法（v2ray-core 内部统一转小写后匹配）。

关键概念：路由是从上到下顺序匹配的——第一条命中的规则决定了这条流量的去向。在「流量走向」图里，每条规则会画一张小卡片，命中关系一目了然。

自动同步：改了出站的 tag 后，路由区块会自动重新渲染，规则下拉里会即时反映新的 tag；删掉的 tag 也会从规则和 balancer 里清掉，不会留死引用。

负载均衡器

在路由区块底部可以添加 Balancer——把多个出站绑成一组，按策略分配流量。

每个 Balancer 卡片字段：

  • tag：引用名（如 balancer-overseas）
  • selector：选哪些出站加入这个组。以色块按钮的形式列出当前所有出站 tag，点一下就加入 / 移除
  • strategy：roundRobin（轮询）或 leastPing（选最低延迟）

添加 balancer 后，路由规则的下拉里会出现 balancer tag，可以选它作为 outboundTag。注意：

  • 选择器至少 2 个出站，否则会出现 ⚠ 警告（少于 2 个的 balancer 等同普通出站，建议改用路由规则）。
  • 如果把代理出站（vmess/vless/trojan/...）和非代理出站（freedom/blackhole/dns）混在一起选，会触发「混选协议」警告——这种组合一般不是想要的。

多个出站组成 balancer 后，「流量走向」图会用一个虚线框把它们圈为一组，便于看清分组关系。

DNS / 日志 / 策略

这三个标签对应配置文件里的 dns、log、policy + 全局 transport。

  • DNS：表单化的 hosts 静态映射 和 servers 服务器列表。新手通常不需要填，保持默认（系统 DNS）即可；只有遇到 DNS 污染问题才需要自定义。
  • 日志：loglevel（debug / info / warning / error / none）和可选的 access / error 文件路径。debug 最详细但很吵，warning 是日常推荐级别。
  • 策略 + 传输：
    • 策略（policy）：连接超时、流量统计开关，绝大多数场景保留默认。
    • 全局传输（transport）：用于 sockopt 类的全局 socket 选项；绝大多数场景省略。

流量走向可视化

当配置里至少有一个入站和一个出站时，「流量走向」卡片会自动出现在配置卡片上方，实时反映当前配置。它不是简单的列表，而是一张自动布局的有向图，按以下顺序绘制：

应用 → 入站 → 路由匹配 → [规则卡片] → 出站 / 负载均衡 → 目标

每种节点用不同语义色标识：

节点颜色含义
入站蓝应用连进来的入口
路由 / 规则黄流量匹配位置
代理出站紫流量走代理
直连出站绿流量直连（freedom）
拦截出站红流量被丢弃（blackhole）
负载均衡器橙多出站组
目标深色最终访问的目标网站

连线上还会标出传输协议，比如 WS / TLS、TCP / REALITY，让你一眼看出每条出站用了什么传输。

当 balancer 内有 2 个以上出站时，它们会被一个虚线框圈成一组，共享一条合流箭头指向目标；当同一出站被多条规则命中时，规则卡片之间会显示「自上而下 · 命中即停」的提示。

在画布上方有一条提示文字，总结当前配置的「规则数 / 负载均衡数 / 未被 balancer 引用的剩余出站数」，方便快速发现遗漏的出站。画布下方还有一个图例，只列出当前配置里实际出现的路径类型，不需要的不会显示。

流量走向图卡片标题右侧有一个 ▾ 箭头，点一下可以折叠整张图；再点一下展开。

JSON 模式

点「JSON」标签切到原始 JSON 视图。这一侧是给需要精确控制 / 调试 / 排查错误的人用的：

  • 左边的行号栏（#jsonGutter）会随滚动同步。
  • 顶部显示字符数。
  • 按 Tab 键插入 2 个空格，不会跳到下一个控件。
  • 点「⟳ 格式化」会用 2 空格缩进重新序列化（仅在 JSON 模式可见）。如果 JSON 不合法，会弹「JSON 格式不正确，无法格式化」。
  • 从可视化切到 JSON 时，表单内容会先同步到编辑器；反之，JSON 内容合法时会同步回表单（不合法则保留原状态，避免丢数据）。

建议工作流：日常编辑用「可视化」模式；遇到高级字段缺失或想验证 JSON 兼容性时切到「JSON」模式排查。

保存与应用

所有改动都在内存里，需要点「保存」才能落盘。后台流程：

  1. 收集当前状态（如果是可视化模式，会从表单提取所有字段）。
  2. 序列化为 JSON，写到 config.json。
  3. 如果 v2ray 正在运行，会自动重启以加载新配置；如果是停止状态，只落盘不启动。
  4. 顶部状态指示器刷新，Toast 弹「配置已保存并应用」或「保存失败: {原因}」。

键盘快捷键 ⌘/Ctrl + S 等同点保存按钮。未保存的修改离开页面前，浏览器会弹原生确认框防误关。

如果只是想把服务器配置重新拉一次（比如另一个人在命令行改了文件），点顶栏的 ↻ 刷新。如果当前有未保存的改动，会弹「当前有未保存的更改，确定要重新加载吗？」的二次确认。

启动、停止与重启

状态 Hero 区有 3 个按钮，按当前状态自动启用 / 禁用：

当前状态启动 ▶停止 ■重启 ↻
已停止可用禁用禁用
运行中禁用可用可用

运行中时，状态卡片会显示运行时长（每秒刷新）和响应延迟（来自 /api/status 轮询的实测值）。

导入、导出与复制

配置卡片右上角有三个工具按钮：

  • ⧉ 复制：把当前 JSON 复制到剪贴板。如果在 JSON 模式，复制的是编辑器里的内容；否则是表单生成的最新 JSON。在非 HTTPS 环境下会自动回退到 execCommand 方案。
  • ⬇ 导出：下载为 v2ray-config-2026-08-13T12-34-56.json（文件名带 ISO 时间戳）。
  • ⬆ 导入：选择本地 .json 文件 → 解析 → 切换到可视化视图。如果解析失败弹「文件解析失败: {err}」。

常见操作流程

① 第一次搭建客户端（最常用）

  1. 在「快速模板」点 SOCKS5 + VMess。
  2. 「出站」标签 → 展开 vmess 卡片 → 把 address（服务器地址）、port（服务器端口）、id（UUID）改成你的服务器信息。UUID 不记得了可以点旁边的 🎲 重生成一个本地的——但你得把它同步给服务端才有用。
  3. 如果服务器用 WS+TLS，再展开「传输设置」→ network=ws、security=tls → 填 path、tlsSettings.serverName。
  4. 点「保存」→ 顶栏状态变成「运行中」→ 浏览器系统代理 / 客户端工具指向 127.0.0.1:10808 即可。

② 加上国内 IP 直连（分流）

  1. 确保 geoip.dat 已在工作目录。
  2. 「路由」标签 → 点 🇨🇳 添加：本地 IP → 在弹出的两个 chip 里选 🌐 使用 geoip 关键字。会自动插入规则 ip: ["geoip:cn"]，outboundTag 默认指向 direct（确保有一个 freedom 出站，tag 是 direct）。
  3. 点「保存」即可。

③ 配多个服务器做负载均衡

  1. 先在「出站」里添加两个 vmess/vless 出站，tag 分别起名，比如 proxy-01、proxy-02。
  2. 「路由」标签底部 → 添加 Balancer → tag 填 my-balancer → selector 里点选 proxy-01 和 proxy-02 → strategy 选 roundRobin。
  3. 回到上方某条规则的 outboundTag 下拉，选 my-balancer。
  4. 点「保存」。「流量走向」图里就能看到 balancer 用虚线框圈住两个出站。

④ 从服务器拷贝配置到本机

  1. 在服务器 curl http://server:8080/api/config 拿到 JSON。
  2. 本机打开 Web → 顶栏「⬆ 导入」或引导页「从文件导入」 → 选文件。
  3. 检查服务器地址、UUID 等是否需要改 → 「保存」即可。

排错提示

大多数问题都会通过 Toast 弹出来，这里汇总几种典型情况：

现象原因 / 怎么办
「文件解析失败: Unexpected token ...」导入的 JSON 格式坏了。常见：末尾多了逗号、用单引号、用注释。
「保存失败: unknown field ...」JSON 里出现了 v5 字段名（transport / router / transportSettings）。本项目用 v4 格式，按 字段名兼容性对照 修改。
状态一直是「异常」v2ray-core 启动失败。多半是 geoip.dat / geosite.dat 缺失，或路由规则引用了不存在的 tag/balancer。点 ⌘/Ctrl+S 保存后看终端日志。
「至少保留一个 XXX」删最后一条入站/出站时被拒绝。V2Ray 必须至少 1 入 1 出。
Balancer 选择器提示「至少 2 个出站」balancer 选太少不会报错，但等价于普通出站。建议要么补到 2 个+，要么改用路由规则。
点了「刷新」但页面没变化勾选过「有未保存的更改」的二次确认，取消了 → 状态保持不变是正常的。

开机自启

macOS

以下按推荐程度排序，列举几种主流的开机自启方式。

1. LaunchAgent（推荐）

最标准的方式，通过 plist 配置文件注册为系统服务。将以下文件保存到 ~/Library/LaunchAgents/com.v2ray.console.plist：

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
  "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>Label</key>
    <string>com.v2ray.console</string>
    <key>ProgramArguments</key>
    <array>
        <string>/Users/你的用户名/v2ray-console/v2ray-console</string>
        <string>-config</string>
        <string>/Users/你的用户名/v2ray-console/config.json</string>
        <string>-port</string>
        <string>8080</string>
    </array>
    <key>WorkingDirectory</key>
    <string>/Users/你的用户名/v2ray-console</string>
    <key>RunAtLoad</key>
    <true/>
    <key>KeepAlive</key>
    <true/>
    <key>StandardOutPath</key>
    <string>/Users/你的用户名/v2ray-console/stdout.log</string>
    <key>StandardErrorPath</key>
    <string>/Users/你的用户名/v2ray-console/stderr.log</string>
</dict>
</plist>

加载生效：

# 加载（注册服务）
launchctl load ~/Library/LaunchAgents/com.v2ray.console.plist

# 手动启停
launchctl start com.v2ray.console
launchctl stop com.v2ray.console

# 查看状态
launchctl list com.v2ray.console

# 卸载自启
# launchctl unload ~/Library/LaunchAgents/com.v2ray.console.plist

plist 存放位置的区别：

位置用户上下文适用场景
~/Library/LaunchAgents/当前用户登录后启动个人程序（最常用）
/Library/LaunchAgents/任意用户登录后启动所有用户共享
/Library/LaunchDaemons/系统启动时（root）系统级服务

常用 key 说明：

Key说明
RunAtLoad加载时立即运行
KeepAlivetrue 表示崩溃/退出后自动重启
WorkingDirectory指定工作目录（需要包含 geoip.dat / geosite.dat）
StandardOutPath / StandardErrorPath日志输出路径
EnvironmentVariables设置环境变量（如 {"PATH": "/usr/local/bin:..."}）

注意：如果配置使用了 geo 规则，geoip.dat 和 geosite.dat 需放在可执行文件同目录（v2ray-core 按二进制目录查找，而非工作目录；LaunchAgent 示例中 WorkingDirectory 恰好同目录）。未使用 geo 规则可忽略本条。

2. 系统设置 → 登录项（GUI 方式）

系统设置 → 通用 → 登录项与扩展，点 + 添加 v2ray-console。

适合一次性配置，图形化操作。本质也是往 ~/Library/LaunchAgents/ 写 plist，系统帮你管理。

sfltool add-item com.apple.LSLoginItem /path/to/v2ray-console/v2ray-console

4. Shell 配置注入（轻量方案）

在 ~/.zshrc（或 ~/.bash_profile）末尾添加：

# 后台运行 v2ray-console（仅在打开终端时触发）
(pgrep -x v2ray-console > /dev/null || ~/v2ray-console/v2ray-console -config ~/v2ray-console/config.json -port 8080 &) > /dev/null 2>&1

限制：只在打开终端时触发，不是真正的开机自启。适合开发阶段临时使用。

Linux（使用 systemd）

创建 systemd 用户服务（推荐，无需 root）：

# 假设 v2ray-console 在 ~/v2ray-console/ 目录
mkdir -p ~/.config/systemd/user

cat > ~/.config/systemd/user/v2ray-console.service << 'EOF'
[Unit]
Description=V2Ray Console Management Panel
After=network.target

[Service]
Type=simple
ExecStart=%h/v2ray-console/v2ray-console -config %h/v2ray-console/config.json -port 8080
WorkingDirectory=%h/v2ray-console
Restart=on-failure
RestartSec=5
StandardOutput=append:%h/v2ray-console/stdout.log
StandardError=append:%h/v2ray-console/stderr.log

[Install]
WantedBy=default.target
EOF

# 重新加载 systemd 用户配置
systemctl --user daemon-reload

# 启用开机自启
systemctl --user enable v2ray-console

# 立即启动
systemctl --user start v2ray-console

# 查看状态
systemctl --user status v2ray-console

# 查看日志
journalctl --user -u v2ray-console -f

# 卸载自启
# systemctl --user stop v2ray-console
# systemctl --user disable v2ray-console
# rm ~/.config/systemd/user/v2ray-console.service

如果希望作为系统服务（所有用户可用，需要 root）：

sudo cat > /etc/systemd/system/v2ray-console.service << 'EOF'
[Unit]
Description=V2Ray Console Management Panel
After=network.target

[Service]
Type=simple
ExecStart=/opt/v2ray-console/v2ray-console -config /opt/v2ray-console/config.json -port 8080
WorkingDirectory=/opt/v2ray-console
Restart=on-failure
RestartSec=5
User=nobody
StandardOutput=append:/opt/v2ray-console/stdout.log
StandardError=append:/opt/v2ray-console/stderr.log

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable v2ray-console
sudo systemctl start v2ray-console

路径说明：%h 在 systemd 用户服务中自动展开为用户的家目录路径。如果 v2ray-console 安装在其他位置，请相应调整 ExecStart 和 WorkingDirectory。

Windows（使用 NSSM）

Windows 下推荐用 NSSM（Non-Sucking Service Manager）将 v2ray-console 注册为系统服务，实现开机自启和崩溃自动拉起。参考：NSSM 使用指南。

1. 安装服务

从 nssm.cc 下载并解压 nssm.exe（建议放入 PATH），以管理员身份打开 PowerShell / CMD：

:: 安装服务（路径按实际安装位置调整）
nssm install v2ray-console C:\Users\你的用户名\v2ray-console\v2ray-console.exe

:: 启动参数
nssm set v2ray-console AppParameters "-config C:\Users\你的用户名\v2ray-console\config.json -port 8080"

:: 工作目录（config.json 用相对路径时以此目录解析）
nssm set v2ray-console AppDirectory C:\Users\你的用户名\v2ray-console

:: 日志输出
nssm set v2ray-console AppStdout C:\Users\你的用户名\v2ray-console\stdout.log
nssm set v2ray-console AppStderr C:\Users\你的用户名\v2ray-console\stderr.log

:: 启动服务
nssm start v2ray-console

服务默认为「自动」启动类型，开机即自启；进程异常退出后 NSSM 会自动重启（相当于 KeepAlive）。

2. 日常管理

命令说明
nssm start v2ray-console启动服务
nssm stop v2ray-console停止服务
nssm restart v2ray-console重启服务
nssm status v2ray-console查看服务状态
nssm edit v2ray-console打开 GUI 编辑服务配置

3. 卸载自启

nssm stop v2ray-console
nssm remove v2ray-console confirm

注意：

  • nssm install / set / remove 等写操作需要管理员权限。
  • 如使用 geo 规则，geoip.dat / geosite.dat 放在 exe 同目录即可（v2ray-core 按二进制目录查找）。
  • 局域网访问（-host 0.0.0.0）需放行防火墙：netsh advfirewall firewall add rule name="v2ray-console" dir=in action=allow protocol=TCP localport=8080

六、Security 传输层安全

6.1 TLS

"streamSettings": {
  "security": "tls",
  "tlsSettings": {
    "serverName": "your-server.com",
    "allowInsecure": false,
    "alpn": ["h2", "http/1.1"],
    "minVersion": "1.2",
    "maxVersion": "1.3",
    "cipherSuites": "",
    "certFile": "/path/to/cert.pem",
    "keyFile": "/path/to/key.pem",
    "pinSHA256": ["cert-sha256-hash"]
  }
}
字段默认值说明
serverName空SNI，CDN/反代场景建议填写，不填则不发 SNI
allowInsecurefalse是否允许不安全证书（客户端开发可开）
alpn空ALPN 协商，如 ["h2", "http/1.1"]
minVersion"1.2"最低 TLS 版本
maxVersion"1.3"最高 TLS 版本

常见误区：serverName 在客户端留空不会导致 TLS 握手失败，但很多 CDN（如 Cloudflare）靠 SNI 路由，所以建议填上。

6.2 Reality

Reality 是 VLESS 的专属安全传输，无需 TLS 证书即可实现 TLS 级别的加密和域名伪装。

"streamSettings": {
  "network": "tcp",
  "security": "reality",
  "realitySettings": {
    "serverName": "www.microsoft.com",
    "fingerprint": "chrome",
    "show": false,
    "publicKey": "...",         // 客户端：服务端公钥
    "privateKey": "...",        // 服务端：私钥
    "shortId": "0123456789ab",  // 短 ID（8 位十六进制）
    "spiderX": "/",             // 爬虫路径
    "dest": "www.microsoft.com:443",  // 服务端：回落目标
    "serverNames": [            // 服务端：可接受 SNI 列表
      "www.microsoft.com"
    ]
  }
}
字段说明
fingerprintTLS 指纹：chrome / firefox / safari / random / randomized
serverName客户端：伪装成访问该域名
publicKey客户端：服务端公钥（由服务端的私钥生成）
privateKey服务端：用 xray x25519 生成
shortId服务端：作为连接标识，匹配不上则回落

Reality 当前需要服务端配合 xray 或 v2ray-core v5+ 使用。Reality 是无证书的 TLS 替代方案，被视为目前最安全的传输方式。

"outbounds": [{
  "mux": {

  }
}]
字段默认值说明
enabledfalse是否启用多路复用
concurrency8单个 TCP 连接上最大并发复用数（建议 4~16）

Mux 用一条 TCP 连接承载多个虚拟连接，减少握手开销。但在高延迟网络下可能降低吞吐。建议先关着，只有遇到大量短连接场景（如浏览器上网）才考虑开启。

八、Routing 路由

路由是整个配置中最核心的流量控制子系统。

{
  "routing": {
    "domainStrategy": "AsIs",
    "domainMatcher": "linear",
    "balancers": [],
    "rules": [],
    "settings": {
      "domainStrategy": "AsIs",
      "domainMatcher": "linear",
      "rules": []
    }
  }
}

注意：v4 格式中路由配置在 routing.settings.rules 下。routing.rules（顶层）是 v5 格式。当前项目使用 v4 格式，请使用 routing.settings.rules。

8.1 域名策略

domainStrategy说明
"AsIs"不解析，直接匹配域名原文（最快）
"IPIfNonMatch"如果域名规则未匹配，则解析为 IP 再匹配 IP 规则
"IPOnDemand"所有域名先解析 IP，再匹配 IP 规则

推荐 "AsIs"。如果大量使用 geoip: 规则才考虑 "IPIfNonMatch"。

8.2 域名匹配器

domainMatcher说明
"linear"线性匹配，简单稳定（默认）
"mph"最小完美哈希，大量域名规则时内存更优

8.3 路由规则

每条规则按从上到下顺序匹配，匹配后停止。

"rules": [
  {
    "type": "field",
    "domain": ["geosite:cn", "domain:baidu.com"],
    "ip": ["geoip:private", "geoip:cn"],
    "port": "0-100",
    "network": "tcp",
    "source": ["10.0.0.0/8"],
    "protocol": ["http", "bittorrent"],
    "inboundTag": ["socks-in"],
    "attrs": "...",
    "outboundTag": "direct",
    "balancerTag": ""
  }
]
匹配字段格式说明
domain数组域名规则（支持 domain: / geosite: / regexp: 前缀）
ip数组IP 规则（支持 geoip: 前缀）
port字符串端口或端口范围 "0-1024" / "80,443"
network字符串"tcp" / "udp"
source数组源 IP 段
protocol数组"http" / "tls" / "bittorrent"
inboundTag数组按入站标签匹配
outboundTag字符串匹配后使用的出站
balancerTag字符串匹配后使用的负载均衡器
域名规则前缀
前缀示例说明
domain:domain:google.com精确匹配 google.com 及其子域名
geosite:geosite:cn从 geosite.dat 读取域名列表
regexp:regexp:.*\.googlevideo\.com正则匹配
无前缀baidu.com等同 domain: 精确匹配
纯文本子串"sina.com"匹配包含该子串的域名

8.4 负载均衡 (Balancers)

{

    "settings": {

策略说明
"roundRobin"轮询
"leastPing"选延迟最低的出站

常见问题

配置加载失败：unknown field

配置文件使用了 V2Ray v5 JSONv5 格式的字段名（如 transport、transportSettings、router）。请使用 V2Ray v4 JSON 格式（network、wsSettings、routing），与官方 Docker 镜像保持一致。

找不到 geoip.dat

geoip.dat / geosite.dat 不是运行必需的，只有配置引用了 geoip: / geosite: 前缀时才需要——包括 geoip:private（它同样从 geoip.dat 加载，并非内置）。规则只用裸 IP 段（如 10.0.0.0/8）或具体域名、或完全没有 routing 配置，则无需这些文件（内置模板「SOCKS5 + 内网直连」即不依赖它们）。

报错有误导性：配置引用了 geo 规则但文件缺失时，v4 加载失败后回退到 v5 加载器，最终报 unknown field "grpcSettings" 之类的错——真实原因是 geo 文件缺失，与该字段无关。

文件查找顺序：可执行文件所在目录 → V2RAY_LOCATION_ASSET 环境变量指定的目录 → /usr/local/share/v2ray 等系统目录。下载命令见快速开始。

端口被占用

默认 SOCKS 入站使用 1080 端口。如果端口冲突，在 Web 界面中修改配置文件的 inbounds[].port 即可。
